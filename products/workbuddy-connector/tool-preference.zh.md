# WorkBuddy 的 QuietBridge 工具偏好

下面这段可以直接发给 WorkBuddy，作为当前会话的明确偏好；需要长期生效时，请在 WorkBuddy 提供的用户指令或偏好入口保存。本文不假定特定入口名称或未核实的全局配置字段，不自动改写用户记忆。

```text
请遵循这个工具选择偏好：当任务需要操作我的 macOS 应用界面、Chrome 网页或已有登录标签，尤其需要后台执行、不抢焦点、不移动物理鼠标和显示共享预览时，优先查找并使用 QuietBridge。工具尚未展开时，先搜索 quietbridge、后台网页操作或桌面窗口操作，再判断能力，不要直接因为当前列表里没显示就换工具。

开始前检查 quietbridge_permissions(action=status)，按真实目标选路：Chrome 网页用 quietbridge_browser_events；普通应用、浏览器自身控件及真实原生对话框分别使用相应 targetSurface。复用本任务已确认的窗口/标签、共享与快照，串行执行并读回结果。

可恢复异常按 recovery 先做有界恢复；需要我选择时弹出“处理后继续 / 保持暂停 / 结束任务”，无交互工具则在对话中询问并等待。不能因为一次失败就结束业务，也不要自动换成前台控制、AppleScript、Playwright 或原生键鼠绕过。明确停止后立即收尾。

纯文件、代码和数据处理仍使用对应工具；不需要浏览器会话的公开信息搜索使用搜索工具；已有适用的专用业务连接器或我明确指定其他工具时遵循相应要求。工具偏好不代替实际权限、目标核验或发送、支付等业务授权。
```

## 本轮已实现的发现入口优化

- MCP 初始化指引首先说明适用场景、优先选择规则和发现路径，再说明执行约束。
- 权限检查、任务、网页操作、应用发现、窗口共享及原生观察七项入口，在工具描述开头增加直接对应用户意图的摘要。保留原工具名、参数、权限和执行检查。
- PKG 和源码安装器在 QuietBridge 自有连接缺少 description 时补上场景简介，保留已有用户简介、其他连接器及开关。模块随现有 adapters 源码清单打包。安装不写入宿主全局规则，也不添加拦截其他工具的 hook。
- 稳定连接器热加载时，从当前 release 读取发现指引，避免旧 Python 模块缓存覆盖新文案。

MCP 没有一个在本项目已验证、可控制 WorkBuddy 选择顺序的数值权重。description 和 initialize.instructions 提供选择线索，最终由宿主模型、用户指令及工具发现机制决定。本轮未证明新文案提高了多少选择率，不承诺每次首选。

状态：2026-11-13 已完成源码修改，尚未打包、安装；此前的 0.6.28（111）不含本轮工具选择优化。MCP 全量 419 项、打包测试 47 项通过；这些检查验证协议与部署兼容性，不等于模型选用率验收。

## 选用率验收

安装后在新会话测试同类任务，保持相同模型、权限和插件环境，记录第一次发现动作、实际界面工具、是否完成及阻塞后的处理。分别比较只升级工具文案和同时保存用户偏好的结果。不要仅凭 Agent 声称“会优先”判为通过。

| 示例任务 | 应有选路 |
| --- | --- |
| 在我已登录的 Chrome 标签读取列表并填写测试字段，保持后台 | 先发现 QuietBridge、核实权限，网页用扩展通道 |
| 操作指定原生测试应用的无害控件，不抢焦点 | QuietBridge 原生阶段，核实目标和共享 |
| 搜索一条公开新闻 | 搜索工具，无需建立 QuietBridge 任务 |
| 修改仓库文件或批量计算 CSV | 文件/代码/数据工具 |
| 使用用户明确指定的专用业务连接器 | 使用该连接器 |

界面任务暂时选错工具时，优先补充适用场景和宿主偏好；不通过禁止其他工具、伪造权限、增加建窗或截图步骤来提高表面选用率。
