## 后续代码复核修正：导航也有调试前置

复核 `BackgroundBrowser.run` 后发现，navigate 虽然在 execute 内使用 tabs.update，但 run 会先调用 protect；protect 会建立调试连接、启用 Page 域并安装弹窗保护。因此上文对“首次截图可能首次附加”的描述不完整，不能据此认定本轮 screenshot 是首次 attach/enable。此前导航通常已执行它们；仅凭旧日志仍无法证明当时连接是否持续存在。恢复与截图时间接近的观察保留，但首次 attach 的因果推断撤回。

0.6.16 / 扩展 0.4.7 新增固定阶段 render_probe，inspect 可报告本会话追踪的 attached/pageEnabled 状态；它不等于系统中其他调试器状态。各阶段不进入输入命令的 protect/arm 前置链路。layout 只查询布局并缓存当前绑定/文档/epoch 视口 30 秒；capture 只用该视口执行一次截图，调用前消耗缓存，不自动重复，不导出图像。旧扩展在能力核验时拒绝探针，不把未知命令派发给旧版。

下一轮优先做“inspect → layout → capture → 一次后续导航”的同一流短对照。已 attached/enabled 时不重新连接，也不称为首次连接实验。只有 inspect 证明未附加时，才可按预先约定分别 attach/enable，并留观察窗口；导航/create_target 已可能附加，不能把这些动作放在首次连接对照前而不记录。
