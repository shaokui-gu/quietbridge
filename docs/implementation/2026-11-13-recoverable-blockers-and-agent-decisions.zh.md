# 可恢复阻塞与 Agent 决策

日期：2026-11-13。状态：已打包为 **0.6.27（110）**，扩展保持 **0.4.14**；包内容、签名及隔离检查通过。用户于当日反馈“本次测试通过”，本轮现场验收据此记录为通过。此前的 0.6.26（109）不包含本轮修改。

## 处理原则

业务任务和一次界面操作阶段分别处理。窗口消失、快照过期、候选变化、通道等待、回执超时都不等于业务结束。一次关闭窗口不能证明用户取消；连续关闭只触发暂停选择。用户明确结束、宿主停止或 QuietBridge“停止此会话控制”才是停止信号。

| 情况 | 处理 |
| --- | --- |
| 快照过期、原标签候选变化、通道或映射尚未就绪 | 只对原目标有界刷新、等待或重新观察；通常最多两次检查，仍失败再选择 |
| 命令回执超时、执行进程中途退出 | 先查询原 commandId 或观察既有结果；不能把未知结果写成“未执行”，不能重放输入 |
| 已确认关闭的本任务自建 Chrome 专用窗口 | 接续恢复链，最多自动替换两次；第三次关闭暂停选择，不推断取消 |
| 原生窗口、用户已有窗口、仅标签关闭或关闭证据不足 | 检查原目标；无法安全继续时暂停选择，不自动选择另一个窗口 |
| 权限、真实调试器限制、其他会话占用 | 说明具体原因并请求选择；保留原有限制，不替用户授权或接管 |
| 明确取消、宿主停止 | 释放自己的资源并停止，不再要求继续选择或重建 |

这些规则同时用于执行 worker 和公共会话路由入口，避免在进入 worker 前出错时退回旧的“直接报告并结束”处理。

## 统一选择协议

`structuredContent.recovery` 包含 `taskMustEnd`。可恢复异常和待决策阻塞为 false；明确停止为 true。立即需要选择时 `suggestedNext=ask_user_choice`，自动恢复耗尽时为 `recovery.onExhausted=ask_user_choice`。

`recovery.userDecision` 提供以下约定：

- `presentation=agent_dialog`，优先调用宿主可用的 `AskUserQuestion` 或等效交互工具；不可用时在对话中询问并等待。
- `when=now` 表示立即请求选择；`after_automatic_recovery_exhausted` 表示先完成有界恢复。
- 说明实际阻塞原因，提供“处理后继续 / 保持暂停 / 结束任务”；窗口重建场景使用“重建后继续”。`autoSelect=false`，不能默认代选或把无回复视为同意。
- 等待时停止新输入、释放自己的共享，保留业务结果。具体恢复规则要求保留绑定时保留；失效界面阶段可 end，不能把阶段 end 当作用户取消业务。
- 选择继续后，重新核实权限、连接、目标、共享与新快照，再执行剩余工作。保持暂停就继续等待，选择结束才收尾业务。

这是连接器给 Agent 的结构化回执和调用指引，不能由 MCP 直接打开 WorkBuddy 弹框。宿主中的 Agent 是否调用交互工具，需要现场验收；不能把单元测试通过称为弹框已验证。

## 窗口恢复证据与预算

完成 `create_target → bind → assign → verify_mapping` 后，桥接端交叉核对扩展创建回执、任务、请求 ID、根标签、浏览器窗口和原生映射，保存最小 `windowCreation` 来源证据。不保存页面正文、填写内容或恢复 URL。

`task status` 遇到目标失效时返回 `targetRecovery`。只有同时满足以下条件才返回 `recreate_allowed`：

1. 是本任务创建并已完成独立映射的 Chrome 窗口，原进程代际一致。
2. 原连接、任务归属、租约和 QuietBridge 应用会话仍有效，宿主未停止。
3. 原生 `windowIdentity` 明确返回 `WINDOW_UNAVAILABLE`，原进程的最新窗口列表也不包含该窗口。空 AX、标题缺失、窗口位于其他 Space、`STALE_APP` 都不构成关闭证明。

恢复次序为：`end(自己的失效阶段) → begin(targetSurface=web_content,recoveryOf=旧taskId) → create_target(已授权普通网页入口) → 核实真实窗口 → bind/assign/verify_mapping/share/snapshot`。本步骤不是重启 Chrome、复制 profile 或接管已有窗口。

`begin(recoveryOf=...)` 再检查关闭证据的新鲜度（120 秒）、原连接和应用会话，并重新检查窗口列表与停止信号。新阶段继承 `rootTaskId / previousTaskId / attempt`。同一来源的重复 begin 只返回仍有效的同一个恢复阶段；已结束或归属改变的阶段不能复活。同一阶段的 create_target 沿用既有去重机制，结果未知时不再创建第二个窗口。

两次自动替换后再次关闭返回 `decision_required`；继续自动 begin 会返回 `RECOVERY_DECISION_REQUIRED`。Agent 不能省略 recoveryOf 开启新根任务来绕过预算。用户明确选择重建后，才可开启新一轮授权阶段。建窗本身失败也暂停选择，不能无限循环。

尚未完成映射就关闭的窗口无法获得上述自动重建证明，走检查与选择流程。重建不恢复丢失草稿，也不证明旧输入失败；提交、支付、发送等未知结果不得重放。
