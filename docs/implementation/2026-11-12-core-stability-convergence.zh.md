# 核心能力收敛：移除实验分支与虚假阻塞

日期：2026-11-12。状态更新：2026-11-13 已打包为 [0.6.26（109）](../releases/0.6.26.zh.md)，扩展 0.4.14，实际包核验通过；未安装或重启现有应用，真实环境验收仍待完成。旧 0.6.25（108）安装包不包含本轮收敛。

## 目标

先稳定“绑定已有窗口 → 观察 → 操作 → 复核 → 释放”的核心流程。Chrome 和原生应用均继续使用系统窗口连续视频。停止把离屏 Chrome 视频呈现问题扩展成额外截图、轮询和验收分支。

## 移除的路径

- 扩展动作后的截图促帧、导航后的截图促帧，以及导航确认后延迟 5 秒的单次截图实验均已移除。普通导航、填写、点击和滚动不再隐式调用截图。
- MCP 不再为这些实验轮询原生预览的 Space 状态，也不再向扩展发布 `windowPreview` 证据或处理 `navigationCapture` 报告。
- 同步时清除遗留实验状态及旧 `previewLease/previewFrame`；不再签发旧截图邮箱租约。即使旧扩展回报帧，也不能恢复该预览路径。兼容模块保留用于遗留协议识别，生产同步不再调用它。
- 保留显式 screenshot 观察与明确诊断时的 render_probe；二者都不属于正常操作的前置步骤。原生窗口流与原生观察能力不受这次删除影响。

## 修正的阻塞

1. **旧任务的未复核动作不再阻塞新任务。** 首次分配新任务时清除旧命令、快照、复核门禁和映射证据，同时保留有界的命令终态收据及 `mayHaveExecuted`，迟到回执不会进入新任务。同一任务内已派发、结果未知的输入仍必须复核，不能通过重分配绕过。
2. **明确未派发的错误不再伪装成结果未知。** 扩展只在动作执行前的保护安装路径被 Chrome 拒绝时声明 `inputDispatched=false`。MCP 校验后返回 `execution.status=not_dispatched`，不再制造“上一个动作尚未 snapshot 复核”的附加门禁。点击已发生、随后子标签 attach 失败时不带这个声明，继续保留真实的不确定性。Chrome 的拒绝本身仍会如实返回。
3. **相同标题可以使用只读窗口元数据区分。** 扩展提供当前活动标签标题及 Chrome 窗口位置、尺寸；原生窗口列表保留对应 bounds。多个同名候选均有完整几何信息、扩展证据未过期且只有一个候选各项差值不超过 2 point 时，使用 `window_active_title_and_bounds` 核验。缺失、过期或仍有歧义时继续报告，不能靠导航改标题、移动或激活窗口来补证。

浏览器内容操作继续固定标签扩展通道，不依赖系统视频产生新帧来证明 DOM 操作是否成功。共享仍需建立并核实目标；截图不能充当连续视频。原生输入保留既有共享首帧、窗口归属和焦点检查。

## 后续验收

安装 0.6.26 并重新加载扩展至 0.4.14 后，使用[核心操作验收提示词](core-control-acceptance-prompt.zh.md)，先跑已有专用窗口的短流程，再核对释放后同窗口重新绑定。无需制造离屏条件，不再安排 7/9 分钟截图实验，也不把 Chrome 跨 Space 持续出帧作为本轮核心控制验收前提。

真实占用、系统权限、Chrome 对其他扩展页面或调试客户端的限制仍然可能阻止操作；保留明确原因，不能用接管、新建窗口或切换输入通道掩盖。Chrome 离屏视频是否持续更新仍未解决，本轮不宣称修复。
