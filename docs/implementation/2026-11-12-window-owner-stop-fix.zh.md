# 窗口占用者识别与按会话停止控制

现有“停止浏览器控制”只向扩展发送 `stop_task`，暂停标签分配，不能释放 MCP 的任务级窗口租约。用户在 WorkBuddy 强停本地测试服务时，也无法知道另一个同名后台采集会话才是占用者。现场证据见 [后台强停核查](2026-11-12-background-stop-ownership-review.zh.md)。

## 最终行为

- 控制面板入口改为“任务与窗口”。每项显示原生窗口 ID、WorkBuddy 会话 ID、QuietBridge 任务 ID；即使扩展未连接或尚未完成标签分配，也能显示持有窗口的任务。
- “停止此会话控制”直接撤销所选任务所属宿主本轮的控制权限，不再等待扩展处理停止命令。相同 sessionId/requestId 的后续工具调用被拒绝，因此本轮不能换一个 taskId 重新抢回目标。后续独立轮次仍可重新验证和建立任务。
- UI 通过任务、ownerId、宿主回执以及会话目录哈希核对身份，再使用 Python 生命周期模块相同的 `host-lifecycle/state.lock` 原子写入停止记录。旧任务、进程已退出、归属已变化或回执不匹配时拒绝操作。
- 界面只原子读取任务快照，不等待执行者可能持有的任务文件锁；原生请求阻塞时，停止记录仍能送达 watchdog。扩展的 `active_task` 同时识别撤销记录，撤回未执行命令和分配。
- 停止顺序为撤销新操作、进入 stopping、关闭本连接原生资源、标记 interrupted。stopping 期间继续按内核所有者锁占住目标，即使活动时间已过期，也不能在清理过程中引入另一个写入者。worker 退出时内核锁自动释放。
- TARGET_IN_USE 回执新增 `structuredContent.targetConflict`，仅包含被证实的占用任务、窗口、PID、模式、冲突范围和可核实的宿主会话 ID；无页面内容、凭据或停止权限。恢复说明引导用户核对对应会话，不允许 Agent 自动接管。
- 后续完成 hook 不覆盖已有停止的首次原因和时间，保留 `user_stopped_in_quietbridge` 的取证语义。

## 边界

此入口停止所选宿主本轮通过 QuietBridge 执行的界面控制并释放它的资源，不终止 WorkBuddy 全部进程、不结束其他会话、不关闭 Chrome、不停止 HTTP 测试服务，也不修改 WorkBuddy 定时计划。若定时任务仍启用，未来独立运行仍可能重新取得空闲窗口；须在 WorkBuddy 中单独暂停对应计划。不能通过杀掉测试服务推断窗口租约已释放。

面板不读取 WorkBuddy 私有数据库来猜测标题或后台任务身份；展示的是已注册的宿主回执和目标租约。停止请求已记录不等于视频捕获已确认退出，面板文案保留等待释放及确认共享关闭的提示。

## 验证

MCP 全量 391 项通过，覆盖占用者元数据、同进程不同 Chrome 窗口独立、历史租约清理、用户撤销后阻止原轮次重新 begin、其他会话不受影响、扩展任务即时失效、首次停止原因保留、原生连接清理完成前保持目标互斥，以及 transport 保持在线时 watchdog 自动收尾。

Swift 菜单及面板相关 27 项、打包回归 47 项通过。原生测试使用隔离目录、真实文件锁和模拟会话，覆盖扩展离线也能停止、任务文件锁被执行者持有仍能停止、生命周期锁互斥、旧 owner 拒绝、失效任务隐藏、选错宿主回执拒绝，以及明暗外观下身份与停止按钮可见。面板渲染产物已检查，未操作实际用户窗口或停止真实任务。
