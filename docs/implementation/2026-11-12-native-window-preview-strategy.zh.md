# Chrome 离屏预览回到系统窗口共享

用户报告 Codex 在同类 Chrome 离屏场景也出现画面不更新，确认该问题跨产品存在。此前 0.6.18 的网页内容定时帧虽然能显示新文档，但表现接近幻灯片，不符合连续共享的产品目标。本记录取消该生产路径，恢复系统窗口连续视频，并加入动作后的有界绘制提醒。

## 产品行为

- Chrome 网页任务与其他应用统一使用 ScreenCaptureKit 目标窗口流；省略范围时使用系统应用捕获，后台 Space 可收窄为目标窗口。
- 扩展不再声明 `browser_preview`，也不再以最高每秒一帧上传预览截图。旧版原生端即使继续下发 `previewLease`，扩展也不会启动定时截图生产。
- 成功完成点击、选择、填写、按键或滚动后，扩展对同一已核验 task/tab/document 发起一次低质量 `Page.captureScreenshot`，只用于促使 Chrome 合成器向 WindowServer 提交当前画面。图像保持在扩展 JS 内并立即丢弃，不进入命令结果、预览邮箱或日志。
- 导航命令不在旧文档上提醒；新文档提交并经观察状态核验后提醒一次。同一文档的多个生命周期事件不会重复提醒。
- 提醒失败是静默的最佳努力结果，不改变原页面命令结果，也不触发重放或原生输入兜底。只读、诊断、显式截图和 `render_probe` 不触发该提醒。
- 不激活标签或窗口、不切换 Space、不使用原生键鼠，也没有回到 headless、`tabCapture` 或定时帧方案。

## 证据与边界

既有 off-space 取证显示系统捕获持续收到完整帧，但 Chrome 离屏画面可能仍是均匀色；随后一次扩展截图可恢复非均匀内容。这里据此采用“动作后触发一次绘制”的策略。Codex 同类现象来自用户现场报告，本次没有对 Codex 做独立取证，因此不能据此认定某个 Chrome 版本或 macOS 版本的单一路径根因。

该策略仍依赖 macOS、Chrome 和 ScreenCaptureKit 的离屏合成行为。若提醒不足以刷新窗口，界面应如实表现为系统窗口流未更新；不能把隐藏截图重新接成幻灯片，也不能声称跨 Space 内容已经完整修复。最终产品验收应覆盖离屏导航、点击或滚动后的系统窗口画面更新、空闲时无周期截图、提醒失败不影响动作结果，以及结束任务后的视频流释放。

## 自动化验证

- Node：110 项完整测试通过，覆盖动作后一次提醒、只读不提醒、提醒失败不改变命令、导航新文档提醒，以及旧 `previewLease` 不再触发周期截图。
- MCP：186 项变更相关测试通过，覆盖浏览器任务改走系统共享、显式应用/桌面范围保留，以及工具说明不再宣称定时帧。完整 363 项套件存在 1 项既有的测试顺序依赖：`test_actual_activity_renews_for_more_than_thirty_minutes` 在标准 discover 中失败，单独运行及与任务/窗口套件一起运行通过；本轮未修改该生命周期实现。
- 打包：47 项测试通过，确认源码改动没有破坏部署与安装握手布局。
- `git diff --check` 通过。

源码改动尚需重新打包安装后做真实离屏窗口流验收；本轮没有启动、激活或切换浏览器窗口。
