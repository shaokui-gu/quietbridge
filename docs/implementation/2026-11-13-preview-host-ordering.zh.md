# 预览紧邻宿主窗口的层级修正

日期：2026-11-13。状态：已打包为 **0.6.28（111）**，扩展保持 **0.4.14**；实际包内容、三组件签名与隔离检查通过，尚未安装。0.6.27（110）不包含本轮修改。

原预览使用 `.floating` 层，显示时调用 `orderFrontRegardless()`，多会话仅维持预览之间的顺序。它跟随宿主的几何位置和 Space，但不与宿主保持相邻层级，因此其他普通应用窗口可处于宿主与预览之间。

本轮修改：

- 单预览和多会话卡片统一使用 `.normal`，取消浮动面板行为。预览紧邻宿主上方；其他应用置前时位于宿主和预览之上。
- 使用 [AppKit 相对窗口排序](https://developer.apple.com/documentation/appkit/nswindow/order(_:relativeto:))，从宿主开始按从后到前的顺序放置卡片；只改变本进程持有的预览面板，不对宿主或其他应用排序、激活或改变焦点。
- 复用 30Hz 跟随循环；宿主没有移动时也检查层级，同一宿主组只由一个跟随者检查。已经相邻时不重复发出排序写入。切换前卡片、显示或布局时立即检查。
- 只用当前屏幕窗口列表核实顺序。`optionAll` 中已隐藏和其他 Space 的窗口不能作为当前屏幕相邻顺序的证据；宿主回到当前 Space 后再核实。
- AppKit 的排序可能在下一轮事件循环才生效。排序未确认时保持窗口设备登记，隐藏内容与阴影、关闭鼠标命中，由后续跟随回调读取实际结果，确认后恢复画面。新面板登记或 Space 迁移仍可在完全透明时调用 `orderFrontRegardless()`，随后以宿主为基准排序；画面不会在此登记阶段显示为全局置顶。
- 原 Space 迁移、捕获目标和视频流独立保留。新增 `panelOrderVerified / panelOrderError`，与 `panelSpaceVerified` 和 `streamReady` 分开报告。0.6.28 层级未确认时直接隐藏；现场闪烁反馈后的[修正](2026-11-13-preview-ordering-flicker.zh.md)将初次/未知状态与已验证宿主的短暂异步排序区分，后者至多保留画面 100ms，诊断继续诚实返回未验证。

这是跨进程窗口的相对排序与持续校正，没有建立跨进程 NSWindow 父子关系，也不承诺系统动画或 Mission Control 期间零帧瞬态。宿主缩小、隐藏或离开当前 Space 时沿用隐藏与重新核实流程。

同日补充：[虚拟鼠标也改为紧邻实际操作目标窗口](2026-11-13-cursor-target-ordering.zh.md)，预览与光标复用 `WindowOverlayOrdering` 的相对排序实现，各自保留独立锚点。合并后的预览及光标相关回归为 68 项通过。

验证结果：

- 51 项预览相关 Swift 测试通过，覆盖相邻关系、外部窗口插入、宿主置前、多卡片排序及选择、错误 PID/层级、隐藏面板、Space、跟随、缩放与诊断投影。
- MCP 全量 419 项通过，`git diff --check` 通过。
- 三个独立测试进程分别模拟宿主、外部应用和预览。只创建透明、无阴影、无鼠标命中的 1×1 窗口；实际 WindowServer 回读确认外部应用位于“预览卡片组 + 宿主”上方，组内没有插入。单预览、三卡片和切换前卡片均通过；前台应用 PID 未变，测试进程和窗口已清理。此验证没有捕获或操作用户真实应用。
- 真实 WorkBuddy 面板的视觉体验待新包安装后验收。

安装后验收：保持普通共享，在用户手动切换其他应用到前台时，确认该应用同时覆盖宿主和预览；再手动点回宿主，确认预览紧贴宿主上方。重复点击、拖动、缩放宿主；有多会话时切换前卡片，确认卡片顺序连续。核对 `panelOrderVerified=true`，未就绪时保留实际错误，不以视频已就绪代替层级验证。最后结束任务，确认共享正常释放。
