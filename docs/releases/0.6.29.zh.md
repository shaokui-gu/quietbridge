# QuietBridge 0.6.29（115）

打包日期：2026-11-15。扩展版本保持 **0.4.14**；Swift 二进制沿用本轮源码构建产物。

本版在 0.6.28 基础上加入 **QuietBridge for DeepSeek Harness** 的完整源码级适配与打包集成，
修复 Python 3.9 源码编码问题、首次 112 包安装失败的文件权限问题，以及真实 profile
测试发现的两个 DSH 生命周期缺陷（任务回执参数形态、宿主重启墓碑）。

## 115：宿主重启后会话恢复修复

114 安装并重启 DSH 后，同一会话被恢复，但工具全部返回
`TASK_CANCELLED: 宿主会话或 Agent 已结束`。根因：DSH 关闭时 bundle 写入
`agent-disposed` 会话墓碑（`sessionEnded=true`），重启后 DSH 用**同一 session id**
恢复会话，lifecycle store 未清理旧墓碑，新进程首个 `turn/start` 被误标为已停止。

修复：

- lifecycle 的 `agent-created` 不再只是忽略：它证明该 session/agent 属于新的宿主进程，
  于是删除该对的 session-wide 墓碑并清除历史 turn 的 `sessionEnded`（保留已停止 turn
  的 `stoppedAt`），首个 `turn/start` 正常建立新 run 的存活轮次；创建本身仍不授予 turn；
- 新增 Python 回归测试（dispose → agent-created → 新 turn 存活）；
- 真实宿主复验：重启后 `permissions`/`apps` 恢复，同一轮 `begin→bind→share→end→begin→end`
  两阶段全部成功，lifecycle store 自动写入两个新 taskId 回执，第二次 end
  `captureStop.stopConfirmed=true`。

114 包存在该重启缺陷，请使用 115。

## 114：真实 profile 全能力测试与回执修复

113 安装成功后，用官方 CLI 把部署的 bundle 加入用户真实 `desktop` profile；运行中的
DSH 即时加载插件（`include:quietbridge-dsh` active，每个 Agent 一个连接器），并由真实
模型经真实 helper 调用全部桌面工具：

- 通过：`apps`（list/find/get/launch）、`task`（begin/bind/status/end）、`windows`
  （list/share/unshare）、`state`、`screenshot`、`visual_state`、`situation`、
  `set_value`、`click`（元素与坐标）、`scroll`、`drag`、`hover`；
  权限 `accessibility=True`、`screenRecording=True`、`responsibleApp=QuietBridge.app`。
- 按设计拒绝（非故障）：`type_text`/`key`/`paste` 对 desktop 绑定任务返回
  `UNSAFE_WINDOW_DELIVERY`，未发生焦点窃取或应用级输入绕过；`wait_ready` 在无
  AXWebArea 的原生窗口返回 `needs_visual_review`。
- 浏览器通道未验收：扩展未连接，`browser_events` 返回 `BROWSER_HOST_UNAVAILABLE`，
  `browser_session` prepare/list 正常。

**发现并修复的缺陷**：DSH session 事件 `tool/call.data.arguments` 是原始 JSON 字符串，
bundle 原样作为 lifecycle `toolInput` 转发，导致 begin/bind 回执被 lifecycle CLI 丢弃；
同一宿主轮次内第一次 task `end` 后，第二次 `end` 会因缺少归属回执而以
`SESSION_ROUTING_REQUIRED` 拒绝。修复：

- `bundle/index.js` 新增 `parseToolArguments()`，统一把 session/tools 三条路径的参数
  归一化为对象，`tools/result` 优先使用已解析的 `exec.arguments`；
- `adapters/deepseek_harness/lifecycle.py` 同时接受字符串与对象 `toolInput`，畸形 JSON 忽略；
- 新增 3 项 Node 测试与 2 项 Python 测试覆盖该形态；
- 在真实宿主复验 `begin→bind→share→end→begin→end` 全部通过，多阶段回执落盘。

113 与 114 包中该回执/重启缺陷仍存在，请使用 115。

## 安装失败修复（112 → 113，114/115 沿用）

0.6.29（112）首次安装失败，`/var/log/install.log`：postinstall 的 deploy.py 在
`codesign --verify --strict -R ... /Applications/QuietBridge.app` 返回 1；直接原因是被安装的
app 内 DSH 适配文件以 `0600` 打入（创建它们的会话使用了严格 umask），PackageKit 保留源
文件权限，安装后变成 `root:wheel 0600`，以桌面用户运行的 postinstall 无法读取，codesign
报 `Permission denied`，Installer 因此失败并回滚用户事务。

修复：

- 归一化仓库工作树文件模式（33 个 0600 文件恢复 0644）；
- `packaging/macos/build.py` 新增 `normalize_tree_modes()`，在签名前把 payload/scripts 的
  目录设为 0755、普通文件 0644、保留可执行文件 0755；
- `tools/release_layout.copy_bridge()` 与 `install.py` 源码部署复制后同样归一化权限；
- 新增 `packaging/macos/test_build_modes.py`（3 项）验证归一化与 bridge 源文件可读，
  防止 `0600` 文件再次进入包；
- 对包内 payload 增加 “文件模式必须 0644/0755” 核验。

112 包（sha256 `2083137a…`）、113 包（`ac5fa0e0…`）与 114 包（`accda57a…`）作废，请使用 115。

## 本轮内容

### DeepSeek Harness 适配

- `adapters/deepseek_harness`：契约文档、配置/生命周期适配、`bundle_render` 与
  `profile_plan`；`bundle/` 为可安装 Host bundle（`@quietbridge/dsh`），每 Agent 一个
  stdio 连接器、宿主环境可信身份、Agent 作用域 `quietbridge_*` 工具、session 生命周期桥接。
- `services/mcp`：新增宿主环境上下文路由（`QUIETBRIDGE_HOST=deepseek-harness` + session/agent
  身份），按 lifecycle store 的 turn 放行/拒绝；Workbuddy token 路径保持不变。
- PKG 部署：`deploy.py` 从已验证 release 事务化渲染
  `~/Library/Application Support/QuietBridge/releases/<digest>/dsh-bundle`，与其它用户文件
  一起提交/回滚；渲染失败只记录，不阻断主安装。
- 验证工具：`tools/dsh_isolated_check.py` 可在临时 `DSH_HOME` 中复现真实宿主安装、
  Agent 工具注册、turn 生命周期、路由放行/拒绝与多 Agent 隔离（`--agents 1/2/3/4`）。
- 安装入口（安装 114 后按 postinstall 输出的 `<digest>` 执行）：
  `dsh plugin --profile <profile> add "$HOME/Library/Application Support/QuietBridge/releases/<digest>/dsh-bundle"`；
  安装后重启 DSH 使修复后的 bundle JS 生效。

### 相对 0.6.28 包的主要差异

- bridge 新增 `adapters/deepseek_harness/`（含 bundle 7 个文件）与相关路由/生命周期代码；
- Workbuddy 连接器补充工具选择 guidance 与恢复/协议小幅更新；
- 所有直接执行的 Python 入口脚本增加 `# -*- coding: utf-8 -*-` 编码声明：验证发现
  `/usr/bin/python3`（3.9）直接执行 `server.py` 时会因多字节字符跨 8192 字节读取边界而误报
  非 UTF-8；加入声明后 3.9 直接执行与 MCP 握手通过，并新增回归测试防止复发；
- Swift 二进制由当前源码重建（源码包含 2026-11-13 的预览宿主层级、光标目标层级与原生输入
  反馈修订），与 0.6.28 包内二进制哈希不同；实际视觉效果仍需安装后验收。
