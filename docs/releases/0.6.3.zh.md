# QuietBridge 0.6.3（build 86）

## 锁屏授权与任务解耦

- Locked use 只处理自动解锁票据、手动认证交接和解锁来源，不再暂停或接管 MCP 业务任务。
- 原生观察/输入只检查 macOS 实时锁屏状态；`manualSuppression` 只阻止自动解锁授权。
- 手动解锁成功后保留同一任务、目标绑定与操作租约；恢复前重新观察原目标及共享状态，不自动重放结果未知的输入。
- `lockedUse=false` 不建立覆盖层、不启动 guardian、不请求系统锁屏；任务状态查询会返回实时锁屏状态。
- 解锁监听独立于授权 socket；覆盖层交还后仍能检测真实系统解锁，不再把旧 `systemLocked=true` 留在 UI/诊断里。
- 授权诊断暴露 `lastUnlockMethod=automatic/manual/null`，区分锁屏由票据自动完成还是由用户认证完成。
- 手动交还确认后只撤销 Locked use 的自动解锁任务授权；业务任务租约及目标绑定仍由原会话拥有和续期。

## 验证及限制

完整 Swift 回归 263 项通过，MCP Python 回归 254 项通过。新增测试覆盖真实会话状态读回、Socket 不可用时的纯状态逻辑、手动解锁保留任务、自动票据仍受限和关闭 Locked use 不建立锁屏覆盖。测试没有真的锁屏或执行用户桌面输入。

已根据 Workbuddy 0.5.40 的历史日志核实：`listWindows` 与 `windowIdentity` 被 `MANUAL_AUTHENTICATION_REQUIRED` 拒绝，且辅助进程的授权 socket 未启动；本版分别移除任务门禁与 socket 依赖的解锁状态观察。真实 macOS 锁屏交接仍须安装后验证。

沿用 0.6.x Bundle ID 和签名证书。PKG 外层无 Developer ID Installer 签名，未公证；本次只构建，不安装。
