# QuietBridge 0.6.15（98）

修复 Workbuddy 在准备阶段持续报告 `host_unavailable` / `browserChannel=False`、但扩展全局心跳正常的问题。扩展仍为 0.4.6；不修改 Chrome 离屏渲染或原生捕获策略。

0.6.14 的路由 worker 在无任务时读取会话私有心跳，而扩展只发现已占用活动任务槽的私有通道。先核验连接再 begin 的正确调用顺序因而无法前进。同一真实配置、同一会话目录的只读对照中，已安装旧函数返回 False，修复函数返回 True；没有重连扩展、启动任务或捕获。

- 无任务 candidates 使用全局扩展元数据，返回真实 clientVersion、connectionScope=extension_preflight、taskChannelReady=false。permissions.browserChannel 同样检查当前应用会话的全局心跳与授权；不要求先 begin。
- 全局准备查询不占任务槽、不创建共享、不剪裁其他任务或复制其命令。taskChannelReady=false 在全局准备阶段是正常值，不意味着扩展离线。
- begin 后仍使用各自私有通道。首次心跳最多等待 3 秒，全局在线而私有未就绪时报告 channel_pending/BROWSER_CHANNEL_STARTING，最多两次只读复查；不要求用户重载扩展、不重建任务、不重复创建目标。
- 私有候选、绑定和命令保持隔离；全局候选不能成为私有 assign 的替代证据。新鲜私有握手的真实权限拒绝仍报告权限错误，不伪装为启动等待。应用 session 不匹配、旧/未来心跳、关闭及全局授权缺失仍阻断。
- 任务开始前后、取消等待、首次 create_target 尚未就绪、旧应用 session、权限拒绝及跨会话候选隔离均有回归测试。工具能力说明与跨 Space 诊断提示词同步更新。

验证：MCP 全量 349 项、打包流程 47 项、诊断分析 8 项通过，原生 Release 构建通过。本轮没有创建真实浏览器任务、共享、截图、导航或重载扩展。实际安装包另行展开验证组件签名、证书/profiles、版本、桥接源码、扩展目录/ZIP、脚本、隔离 MCP 初始化及包内无任务准备检查，结果在 dist/quietbridge-0.6.15-verification.json。
