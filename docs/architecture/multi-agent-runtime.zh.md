首版交付范围已收敛为同一宿主也可使用的最多三路执行会话，预览采用扑克牌堆叠切换，
详见 [三会话并行与卡片预览](three-session-preview.zh.md)。下文四路目标保留为后续扩展验收，
不作为首版三路版本的发布要求。

## 1. 已确认的产品要求

- 原始项目继续使用本仓库，核心能力保持单一来源。
- 一台 Mac 安装一个 QuietBridge.app，负责权限、菜单栏控制、本机服务和组件更新。
- Workbuddy Connector 与 DeepSeek Harness 插件分别按各自规范发布，接入同一个 QuietBridge 应用。
- 隔离单位是 Agent 执行会话，同一个宿主中的不同 Agent 也需要隔离，不能只分成 Workbuddy 和 DSH 两份状态。
- 不同会话能够同时执行、同时保持自己的共享预览；一个会话停止、超时或执行进程崩溃，正常情况下不撤销其他会话。
- 所有界面输入继续遵守不抢用户焦点、不移动物理鼠标、不切换用户 Space、网页不回落原生键鼠的要求。
- 操作入口集中在 QuietBridge 应用控制面板；新增面板和预览状态先更新 Figma，再实现。

这里的隔离包括调用路由、目标、快照、命令、租约、预览和清理。macOS 的系统锁屏、共享剪贴板、目标应用的进程级状态以及浏览器账号状态，需要额外协调；一个登录桌面不能提供虚拟机级的环境隔离。

## 2. 当前实现与差距

| 模块 | 当前实现 | 并行版本的变化 |
| --- | --- | --- |
| MCP 任务存储 | `services/mcp/server.py`、`browser_events.py` 使用唯一 `activeTaskId` | 改为执行会话注册表及其任务集合，调用必须解析到自己的上下文 |
| 桥接状态 | `STATE`、`SHARE_SELECTION`、`POWER_GUARD` 等为桥接进程全局状态 | 每个 Agent 使用独立桥接进程或显式上下文；禁止共享默认目标 |
| 原生资源租约 | `TaskResourceLease.swift` 保护已按连接登记、分别到期；预览仍独占 | 可信执行会话租约、资源集合与撤销状态，不能把共享连接当作不同会话 |
| 原生共享服务 | `SharedHelperServer.swift` 可接受多连接，但共享执行器、资源租约、捕获与调度 | 多连接不等于多任务隔离；拆成主管理服务与会话 Worker |
| 调度 | `RequestScheduler.swift` 对所有桌面请求使用一个执行槽 | 不同隔离目标可并行；仅相关目标和全局资源进入有界仲裁 |
| 致命错误 | 原生不可响应可触发整个共享进程退出 | 一般执行故障只回收对应 Worker；主管理服务继续服务其他 Worker |
| 预览 | `SpacePreview.shared` 为单实例，宿主优先选择 Workbuddy | 每个会话独立捕获流和预览，显式绑定其宿主窗口 |
| 浏览器扩展 | 单个 observer、当前分配和命令结果，全局串行同步 | 按执行会话和任务分路，命令去重、分配、子标签、弹窗与结果分别保存 |
| 防睡眠与 Locked use | 单实例控制器；保护参与者最后一个退出才全局释放 | 继续接入可信执行会话路由与 Worker，完成真实宿主并发验收 |
| Workbuddy 停止回调 | 0.5.53 使用 PostToolUse、FinalStop、SessionEnd 记录任务所有者 | 保留已解决的停止链路，扩展为明确的宿主、会话、Agent 和轮次关联 |

不能通过删掉 `TASK_IN_USE`、复制配置目录或仅把一个预览单例改成字典来满足目标：那会绕过跨会话目标仲裁，并留下原生崩溃、浏览器路由和系统资源的连带影响。

## 3. 推荐运行架构

### 3.1 一个产品应用，多个受管执行进程

QuietBridge.app 是唯一的应用安装和控制入口。应用管理一个本机会话 Broker，并为每个 Agent 执行会话启动独立的原生 Worker。必要的桥接进程属于后台组件，不增加第二个菜单栏应用或第二套用户安装流程。

| 层 | 负责内容 |
| --- | --- |
| 宿主适配层 | 接收宿主真实会话/Agent/轮次身份，注册工具，传递取消和结束事件，提供宿主窗口身份 |
| 会话 Broker | 创建和验证执行上下文、注册会话、目标写租约、Worker 生命周期、资源预算、全局系统状态与组件版本 |
| 会话桥接 | MCP 参数校验、该会话的快照句柄和任务状态、错误恢复说明、与 Broker/Worker 通信 |
| 原生 Worker | 该会话的 AX 操作、窗口定向输入、捕获、原生等待和独立预览；不可响应时可单独终止 |
| 浏览器扩展 | 一个安装实例，内部管理多个任务通道；按标签/窗口归属路由 CDP、快照、截图和命令结果 |
| 应用控制面板 | 显示所有宿主与执行会话、各自预览和操作状态，提供单项停止及明确的全局控制 |

Worker 必须由 QuietBridge 应用的受管启动链创建，签名和责任进程需要在两个真实宿主中核实。不能仅因 Worker 位于同一安装包就声称 macOS 权限归属必然正确。

Broker 不执行可能卡住的 AX 请求，也不等待 Worker 的视频首帧。Worker 退出后只清理其资源；主管理服务不可恢复地退出、用户退出 QuietBridge 应用、系统撤销权限等属于全局事件，应明确报告。

### 3.2 会话身份与调用路由

建议内部身份包含：

| 字段 | 来源与作用 |
| --- | --- |
| `applicationSessionId` | QuietBridge 应用本轮运行生成；退出后全部旧上下文失效 |
| `hostInstanceId` | 经过核验的宿主实例，区分 Workbuddy、DSH 和不同实例 |
| `hostSessionId` | 宿主提供的真实聊天/会话 ID |
| `agentInstanceId` | 实际执行 Agent ID；子 Agent 不能沿用父 Agent 的执行上下文 |
| `executionSessionId` | Broker 生成的执行上下文 ID，跨调用持续存在 |
| `turnId` | 本轮运行身份，用于处理停止后迟到回执和后续新轮次 |
| `taskId`、`leaseId` | 具体任务及本次租约身份 |
| `generation` | Worker 或连接重建代次，阻止旧快照、旧命令和迟到结果进入新任务 |

会话 ID 用于定位，不是授权凭据。Broker 通过受保护 IPC、进程/连接身份和内部会话凭据绑定所有权；模型填写另一个 taskId 不得获得其他会话的控制权。凭据不进入工具描述、对话、诊断正文或截图。

首选每个 Agent 有独立的桥接连接；若宿主共享 MCP 连接，必须由宿主支持的调用中间件或插件执行上下文携带可靠身份，再由适配层分路。不能从当前前台窗口、最后一次工具调用、任务标题、异步 hook 文件的最后写入者或模型自报 Agent 名称猜测调用归属。

**宿主适配验证是并行功能的前置门槛。** 当前已验证的 Workbuddy 停止 hook 不证明每次 MCP 调用都携带可信的 Agent 身份。先验证真实宿主在并发主/子 Agent 调用中的路由能力。若某宿主既不能提供独立连接，也没有可用的上下文扩展点，需要宿主提供接口；在此之前该宿主只能声明已验证的隔离范围，不能宣称支持全部 Agent 并行。

尽量保留现有 `quietbridge_*` 工具名称和参数语义。内部上下文由适配层传递；多任务操作需要消歧时显式要求该会话的 taskId，不再使用跨会话的唯一默认任务。

## 4. 并行和目标冲突规则

会话可以同时活动，不再实施全局单任务互斥。冲突检测覆盖宿主、会话和连接，Broker 是统一的目标写租约权威。

| 场景 | 规则 |
| --- | --- |
| 不同普通应用，使用支持的后台通道 | 并行执行，分别捕获与共享 |
| 同一应用的不同窗口 | 仅在窗口投递和进程级行为经过验证后允许并行；未知或含应用级动作时按目标进程协调 |
| 不同浏览器专用窗口 | 按各自窗口、标签、文档与任务路由，允许并行 |
| 同一浏览器窗口的不同标签 | 逻辑 CDP 可以分路，但窗口视频只显示实际选中的标签；要求同时提供真实任务窗口预览时，为任务使用不同专用窗口 |
| 两个 Agent 写入同一窗口/标签 | 拒绝第二个冲突写租约，返回结构化占用原因；用户确认结束原任务后再重新绑定，不自动接管 |
| 共享页面截图或其他纯读取 | 支持时允许，但每个会话独立快照与结果；观察到状态变化需刷新证据 |
| 跨应用、系统菜单、全局快捷键、共享剪贴板 | 默认并行任务路径不使用；确有必要时进入显式的全局资源策略，不能伪装成独立后台窗口动作 |

目标写租约按真实进程身份/代次与窗口 ID，或浏览器实例/窗口/标签 ID 建立。窗口关闭和 ID 复用必须重新核验。共享同一窗口会互相改变界面状态，因此不能同时给予独立写入承诺。

同一应用进程存在共用菜单、应用状态或 AX 行为时，不应只依靠单条点击的短锁就声称隔离。需要覆盖观察、动作与结果核实的一致性；未验证能力按应用粒度限制，并在状态中说明具体资源冲突，不把所有其他应用任务一起阻塞。

不同浏览器窗口仍可能共用账号、Cookie、Local Storage、Service Worker 和下载配置。任务/标签隔离不等于账号隔离。涉及不同账号或会话副作用时，使用受支持的独立浏览器 Profile，或者明确报告当前共享环境限制，不自动复制用户浏览器数据。

## 5. 多共享与预览

- 每个执行会话拥有独立的捕获目标、共享租约、视频流、画面代次、预览面板和宿主锚点。
- Workbuddy 的预览跟随该 Workbuddy 执行会话的宿主窗口，DSH 同理；两个宿主同时运行时不依赖前台应用来决定归属。
- 同一个宿主窗口承载多个 Agent 时，预览分别标注 Agent/任务，用布局协调器排列，避免重叠；允许单独调整大小、收起、恢复和停止。
- 收起面板只影响显示，继续捕获和执行；停止共享则撤销该会话共享就绪状态，后续依赖共享的输入必须等待恢复，不能把“面板已隐藏”误当成“共享已结束”。
- 停止某个 Agent 时关闭其预览并释放捕获，不让其他面板闪烁、不重建其他会话的视频流。
- 全部任务和预览在 QuietBridge 控制面板中可见；浏览器扩展弹窗保留授权与连接诊断入口。
- 显式桌面共享可能捕获同一显示器上的其他任务画面，应按原有用户选择管理范围，不能宣称与窗口共享具有相同的内容隔离。

资源预算统一管理，单会话有界。首个发布验收目标为最多三路活动会话和三路共享，包含同一个 Workbuddy 内的三个独立会话，采用卡片堆叠切换。两宿主各两个执行会话的四路目标留待后续扩展。根据实测设定正式支持上限；超过上限返回容量状态，不静默关闭其他共享。可降低预览帧率和展示尺寸，但不改变动作坐标语义，也不使用失效画面冒充最新证据。

## 6. 浏览器扩展改造

保留一个 Chrome 扩展及 Native Messaging 注册。扩展内部协议增加多任务路由与能力协商，不安装两套功能重复的扩展。

当前 observer、assignment、lastCommand、createRequest、managedTabs、截图/批注和命令结果改为以执行会话、taskId、generation 分区；页面 ref/snapshotId 还需绑定 tabId、documentId 和导航代次。

- 每个标签的调试连接和命令队列独立；全局注册表变更只占短锁，不让一个网站的加载、截图或等待阻塞所有任务。
- 命令去重、结果查询和结果未知的禁止重放规则继续生效，Worker 重启不能导致其他任务丢失去重记录。
- 创建窗口、子标签、弹窗约束、导航事件与候选证据按任务登记。
- 结束任务只解除该任务的调试连接和钩子；保留用户页面，不清空其他任务的 observer、候选、批注或截图。
- 扩展 service worker 重启可能短暂影响全部通道，应恢复各任务记录后重新核验。浏览器/扩展进程崩溃是共用基础设施事件，不属于单个 Agent 停止。
- 老扩展遇到多任务协议时明确返回版本不兼容和恢复指引，禁止以旧单任务记录解释新消息。

## 7. 停止、故障与全局资源

### 7.1 精确停止

宿主停止事件沿适配层传到 Broker，定位 host/session/agent/turn/lease 的确切集合：

1. 先撤销该上下文的新输入资格，移除其尚未派发的请求。
2. 取消对应原生 Worker 和浏览器任务等待；已下发输入不自动重放或假定回滚。
3. 关闭对应共享流和预览，释放目标写租约及该会话的系统资源参与登记。
4. 持久记录停止代次，拒绝迟到结果重新创建共享或继续输入。
5. Worker 无法响应时，主管理服务回收该 Worker；其他会话继续执行。

每个会话保持独立的活动租约和断连清理。宿主心跳不替代实际操作续租。正常结束、取消、宿主崩溃、连接 EOF、Worker 崩溃和空闲超时分别记录原因。父 Agent 停止是否覆盖子 Agent 按宿主真实执行树决定，只覆盖其实际取消的执行范围；不误伤同一宿主下的其他独立会话。

### 7.2 全局资源的明确例外

| 资源/事件 | 处理方式 |
| --- | --- |
| 防睡眠 | Broker 按有效会话聚合登记；A 结束只移除 A，B 仍活动时保持相应断言 |
| 权限和能力总开关 | QuietBridge 应用统一管理；撤销时向所有相关会话报告，保持拒绝执行 |
| 用户退出 QuietBridge 应用 | 明确的全局退出，取消全部任务并关闭全部共享 |
| Locked use、系统锁屏及用户接管 | 单一系统控制器协调参与者；A 正常结束不因为单独释放而打断仍有效的 B；真实锁屏期间按整机状态等待；手动解锁后保留各任务绑定继续，解锁方式不控制任务生命周期；不承诺每个 Agent 有独立锁屏 |
| 剪贴板 | 后台输入优先 AX 设值/扩展 fill；若保留特定粘贴能力，必须整机独占、校验所有权和恢复，不允许两个 Worker 各自保存恢复而互相覆盖 |
| 公共服务/操作系统故障 | 如 QuietBridge 主服务、浏览器、扩展、WindowServer 故障，可能影响多个会话，明确报告共用故障范围 |

“单个会话停止不影响其他会话”适用于私有资源和正常生命周期清理。系统锁屏、权限撤销和全局退出是产品必须明确表达的共同边界。

## 8. 安装、市场包与版本

- 一个原生 PKG、一套固定应用签名身份、一套浏览器扩展；两个宿主市场包分别发布。
- 稳定连接入口通过受支持的宿主适配配置接入 Broker，不复制原生应用、不维护独立系统权限数据库。
- Workbuddy 与 DSH 同时安装时只新增各自适配注册，卸载一个市场包只撤销其连接与任务，不卸载仍被另一宿主使用的 QuietBridge 应用。
- 协商原生协议、桥接、扩展及宿主适配能力，明确最低版本；旧客户端不能读取并改写多会话格式。
- 升级时旧任务固定到原代次，阻止新任务进入待退役版本；验证可并存版本后才切换。若系统组件无法并存或旧任务必须结束，明确进入维护流程，不把强制重启全部会话称为无影响升级。
- 迁移旧单任务状态只针对已停止的旧任务；活动会话不静默搬迁、猜测归属或恢复历史输入。
- 签名和权限实测先覆盖从两宿主接入的 Worker；现有可选授权插件的严格签名校验必须随架构调整验证，不能放宽身份检查来让多 Worker 通过。

## 9. 分阶段实施与交付门槛

| 阶段 | 具体交付 | 通过标准 |
| --- | --- | --- |
| A：原型验证 | 宿主 Agent 身份路由、两个受管 Worker、两个非激活预览、权限责任归属 | Workbuddy/DSH 的并发调用可唯一定位，Worker 各自出图；遇到宿主接口缺口立即记录，不在错误身份上继续开发 |
| B：会话核心 | Broker 注册、会话私有状态、目标写租约、Worker 生命周期、停止代次 | 不同目标可并行，越界句柄和迟到命令被拒绝；A 停止/崩溃不撤销 B |
| C：并行浏览器 | 多任务扩展协议、每任务窗口/标签/命令分路、单任务清理 | 两个浏览器任务同时填表、滚动、截图，互不串页；停止一项不解除另一项调试连接 |
| D：产品界面 | 先 Figma：多宿主会话列表、并行共享布局、单项停止和全局退出区分；再实现 | 同宿主多 Agent 可识别、预览不重叠、隐藏与结束共享语义清楚 |
| E：系统协调与发布 | 防睡眠聚合、Locked use 协调、安装迁移、版本协商、两个市场包 | 权限责任符合预期；全局事件准确影响相应范围；发布包可分别安装、更新和卸载 |
| F：真实宿主验收 | 单宿主多 Agent、跨宿主并行、长时任务和故障注入 | 达到下列验收标准后才能标注多 Agent 并行支持 |

## 10. 验收标准

1. Workbuddy A/B 与 DSH C/D 四个真实执行上下文并行运行至少 30 分钟；任务 ID、快照、截图、结果、日志与预览均不串会话。优先使用测试文档及独立测试窗口。
2. 两个宿主同时开着时，每路预览持续绑定正确的宿主窗口和目标；移动/跨 Space、调整大小、收起 A 预览不重置 B 的捕获。
3. 在工具执行中、两次工具调用之间、浏览器等待中分别停止 A。以宿主停止事件时间为起点，记录输入撤销与共享关闭延迟；目标为正常路径两秒内关闭 A 预览，B/C/D 不被取消，之后的独立操作仍能成功。已派发系统请求的不可撤回结果单独记录。
4. 注入一个 Worker 的 AX 超时、取消不响应和进程崩溃，只回收该 Worker；其目标写租约安全释放前不允许新任务写入原目标。
5. 两个 Agent 申请写同一窗口/标签时，第二项得到结构化冲突；其他无冲突目标继续执行，无自动接管或隐藏排队到过期后再输入。
6. 验证同一应用不同窗口的后台投递能力；未通过的应用按应用粒度限制，不能把不同进程用例通过外推为全部应用可并行。
7. 用户在其他应用输入、移动鼠标及切换窗口期间，不激活目标或宿主，不挪动物理鼠标、不切换 Space；回执和实机观察都检查。第三方应用自行激活时暂停受影响任务并报告。
8. Chrome 不同任务分别在独立专用窗口运行。绑定、候选、弹窗、子标签、截图与结果对应真实任务；一个任务结束保留其页面且不解除其他任务。
9. 撤销权限、锁屏、退出 QuietBridge 应用时，所有受影响任务准确停止；单个会话正常结束时，其他会话的防睡眠和有效系统参与登记保留。
10. 无 Agent 任务时可保持宿主连接，Worker、捕获流和资源占用按既定空闲策略回收；达到容量上限时返回容量状态，不能悄悄抢走现有会话资源。

## 11. 仓库落地原则

现有模块目录保留，先增加 `adapters/workbuddy/`、`adapters/deepseek-harness/` 与共享的会话接口；Broker/Worker 核心归入原生工程，会话路由归入桥接核心。市场目录只保存各自元数据、加载入口和指令，不复制原生源代码。

先建立已交付版本的可回滚基线，再按上述阶段改造。每阶段保持单会话回归，新增有针对性的隔离、停止和资源冲突测试；真实桌面输入及系统锁屏相关验证另做受控验收。此文档用于实现和验收安排，不代表已安装版本具备这些能力。
